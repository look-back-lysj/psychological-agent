# docs/ADR.md · 架构决策记录（ADR / DR）

> 本文件收录**有取舍的决策**。它不是设计文档（设计文档是 `docs/design.md`），
> 也不是升级计划（那是 `docs/upgrade-plan-v3.md`）——它只回答一个问题：
> **「为什么当时这么定，以及什么时候应该回来重新看。」**

---

## 一、机制说明

### 1.1 什么时候**必须**写一条 DR

满足任意一条就要写：

| # | 触发条件 | 例子 |
| --- | --- | --- |
| 1 | **有取舍**：至少两个都说得通的方案，你选了其中一个 | 「记忆存 JSON 还是 SQLite」 |
| 2 | **否决了 AI 的建议** | DR-001：AI 建议合并「观」+ 仲裁、砍掉「校」，决策人要求保留多 agent |
| 3 | **改变对外可见行为** | 「去掉网页版，浏览器默认不打开」「记忆默认关闭」 |
| 4 | **写进「不能违反」清单** | 「规则层独占 S0/S6」「先完整取回再下发」 |
| 5 | **留下已知代价** | 「多 agent 延迟 +56%~70%，客观指标无改善，但保留」 |

### 1.2 什么时候**不**写

| 情况 | 为什么不写 | 该写到哪 |
| --- | --- | --- |
| 单纯 bug 修复 | 没有取舍，只有对错 | `devlog/dayNN.md` |
| 实现细节（变量名、函数怎么拆） | 读者不关心，改了也不影响决策 | 代码注释 |
| **还没决定的事** | 写了会让人以为已经定了 | `devlog` 的「待办」段，或计划文档 |
| 纯文案调整 | 除非它改变了**对外承诺**（例如人设内核反转，那要写） | `devlog` |
| 有客观唯一答案的事（语法、性能实测） | 不是「决策」是「事实」 | 代码注释 / 评测报告 |

### 1.3 一句判断口诀

> **「如果三个月后有人问『为什么这么做』，而答案不是『因为有 bug』而是『因为我们选了 A 没选 B』，那就写一条 DR。」**

反过来：

> **「如果答案是『因为不这么做会报错』，那不写 DR，去写 devlog。」**

## 二、模板

复制下面这块，把尖括号替换掉。**`与我的建议的差异` 是必填项**，不许留空、不许写「无」了事——
如果确实没有差异，写「AI 建议与决策一致，差异为：无」也算填了。

```markdown
### 决策记录 DR-0XX：<一句话标题>（<YYYY-MM-DD>）

| 项 | 内容 |
| --- | --- |
| **背景** | 为什么要做这个决定。写清**触发事件**（哪次实测/哪份数据/哪个事故）与**当时的约束**（时间、成本、用户边界）。没有触发事件的决定要写出「触发事件：无，属主动收敛」。 |
| **候选方案** | **至少两个**，每条写清「做什么 + 关键代价」。例：① 方案 A：……（代价：……）；② 方案 B：……（代价：……）；③ 不做（代价：……）。 |
| **决定** | 选了什么。用能被人执行的祈使句写，例：「**保留 X，不合并、不删除**」。 |
| **决策人** | 谁拍的。写角色（项目负责人 / 主 agent / 用户）。 |
| **与我的建议的差异** | **必填**。若 AI 建议被否决，必须写清「我建议 X，理由……；决策人要求 Y，故**以 Y 为准**」。若一致，写「AI 建议与决策一致，差异为：无」。 |
| **依据** | 一手来源 + 域名 + **查询日期**。例：`api-docs.deepseek.com`（2026-09-10）。**查不到就写「未检索到，属工程判断」**，不许编。 |
| **已知代价** | 这个决定要付的账。**必须能被验证**，例：「典型轮次多一次调用 → P95 延迟更长」。写了代价就必须有地方记它（成本台账 / 评测报告）。 |
| **如何验证** | 用什么数据/实验来证明这个决定是对的（或不对）。写清**判定规则**与**数据出处**。 |
| **复查触发条件** | 出现什么情况就要回来重新看这条。要写得可判定，例：「当 A/B 数据显示多 agent 组在人工盲评上无优势时」。 |
```

### 字段质量自查

| 字段 | 不合格的样子 | 合格的样子 |
| --- | --- | --- |
| 背景 | 「为了提升体验」 | 「day14 实测 A/B：多 agent 端到端 2146.6ms vs 单模型 1376.0ms，客观指标无差异」 |
| 候选方案 | 只写一个方案 | 写 ≥2 个，各自带代价 |
| 依据 | 「业内共识」 | 「`api-docs.deepseek.com`，2026-09-10；未检索到的部分已标注」 |
| 已知代价 | 「可能有一点性能损失」 | 「典型轮次多 1 次模型调用，成本与 P95 延迟上升；已如实记入 `logs/usage_summary.md`」 |
| 复查触发条件 | 「以后再看」 | 「人工盲评完成且 95% CI 下界 ≤50% 时」 |

## 三、已收录的决策记录

### 决策记录 DR-001：保留多 agent（2026-09-11）

> **原文搬运**：以下表格内容来自 `docs/upgrade-plan-v3.md` §3.5「决策记录 DR-001」，
> **逐字照抄，未改写任何结论**。为符合本文件的新模板，另补了 `背景` / `候选方案` / `复查触发条件` 三项
> （已在字段名后标注「（补）」），补写部分的依据取自 `docs/upgrade-plan-v3.md` §3.5 与 `devlog/day14.md`。

#### 3.1 DR-001 原文

| 项 | 内容 |
| --- | --- |
| **决定** | **保留「观 / 书 / 校」多 agent 架构**，不合并、不删除 |
| **决策人** | 项目负责人（用户） |
| **与我的建议的差异** | 我据上表证据建议：合并「观」与「仲裁」以省一次调用、砍掉「校」的模型自评。用户明确要求**保留多 agent**，故**以用户决定为准**。 |
| **据此执行的折中** | ① 「观」+「仲裁」**保留两次调用**，只把「观」改为**条件前置**（L0 短消息跳过），不影响架构；② 「校」**保留**，但改为**只在本地规则检查命中时才真正调用**，避免它成为每一轮的默认第三跳。两者都不改变「多 agent 存在」这一事实。 |
| **已知代价** | 相比「合并 + 砍校」的方案，典型轮次会**多花调用**（成本更高、P95 延迟更长）。这些代价会被**如实记录**在成本台账里。 |
| **如何验证** | 批次 D 的三组 A/B（单模型 / v3.1 / v4）按第 3.5 节的判定规则跑。**如果数据显示多 agent 组没有优势，我们如实写进评测报告**，而不是掩饰。 |
| **保留的价值** | ① `XINYU_AGENTS=off` 让我们**唯一**能做「有没有用」的对照实验——这本身是《验收清单》的加分项；② 「观」的输出让**策略可解释**（第 3 条硬性要求）；③ 就算最终证明无用，「**我们试过、并用数据砍掉了它**」比「我堆了多 agent」更能体现判断力。 |

> **原文附的一句话**：多 agent 保留，但「**谁有决定权**」不变——规则层拥有安全与策略的最终决定权，
> 模型只在规则划定的范围内补充。**这是安全底线，不因保留多 agent 而让步。**

#### 3.2 按新模板补齐的三项

| 项 | 内容 |
| --- | --- |
| **背景（补）** | 调研阶段（`docs/upgrade-plan-v3.md` §3.5，查询日期 2026-09-11）逐篇核对 arXiv 原文后得出的结论是：**未检索到任何一手证据支持「加一层模型自评 agent 能让回复更像真人」；反而有明确的负面证据**。负面证据包括：arXiv **2310.01798**《LLMs Cannot Self-Correct Reasoning Yet》内在自我纠错使 GPT-4-Turbo GSM8K 从 **91.5 降到 88.0**、Llama-2 从 **62.0 → 43.5 → 36.5**（越纠越差）；同文表 7 显示**同等调用次数下辩论（9 次，83.0）输给多数投票（9 次，88.2）**；arXiv **2311.17371**《Should we be going MAD?》多角色评审 **0.58 < 单 agent 0.60**；arXiv **2306.05685**《LLM-as-a-Judge》显示 judge 本身有位置偏差（交换顺序后仍一致的比率 Claude-v1 仅 **23.8%**）与冗长偏差（被"啰嗦答案"攻击的失败率 **91.3%**）；Anthropic 官方工程博客称多 agent 消耗**约 15× chat 的 token**，且「token 用量单独解释了 **80%** 的性能方差」。<br>⚠️ **上述文献数值为调研阶段引用，属先前核实结果；本次编写 ADR 时未独立复核原文。** 同时必须一起读一条限制：这些论文**测的是推理自纠错，不是人格改写**，因此**不足以否证人设改写本身**（这一点是子 agent 主动指出并如实标注的）。<br>触发事件：调研给出「建议合并/砍掉」的结论，而决策人**不采纳**。 |
| **候选方案（补）** | ① **依 AI 建议合并 + 砍校**：合并「观」与「仲裁」省一次调用、砍掉「校」的模型自评。（代价：丧失多 agent 结构；丧失 `XINYU_AGENTS=off` 这条唯一可做的对照实验资产；「观」输出带来的策略可解释性变弱）<br>② **保留多 agent，但改为条件触发**（**实际采纳**）：保留「观」与「校」两次调用，把「观」改成条件前置、「校」改成只在本地快检命中时真调。（代价：典型轮次多花调用，成本与 P95 延迟更高）<br>③ **完全保留原样（无条件每轮都跑）**：结构最简单。（代价：把「校」变成每轮的默认第三跳，成本最高，且本地快检的价值被浪费）<br>④ **不做对照实验直接砍掉多 agent**：省事。（代价：拿不出「有没有用」的证据，而这正是《验收清单》的加分项） |
| **复查触发条件（补）** | 出现**任意一条**就回来重看 DR-001：<br>① **A/B 人工盲评完成**，且「像不像真人」的配对检验 **95% CI 下界 ≤ 50%**（即无法证明多 agent 更好）→ 届时按 `docs/upgrade-plan-v3.md` §3.5 的判定规则决定是否改用方案①；<br>② **出现成本/延迟硬约束**：`logs/usage_summary.md` 显示单轮成本或 P95 延迟超出可接受区间；<br>③ **危机召回退化**：红队或回归显示多 agent 路径下的危机识别率下降；<br>④ **「观」的输出不再被使用**（例如策略可解释性改成别的方式），此时保留多 agent 的「保留的价值 ②」不成立；<br>⑤ `XINYU_AGENTS=off` 开关因任何原因被移除 → 对照实验资产消失，必须重新评估。 |

#### 3.3 DR-001 现在的事实状态（2026-09-11 之后新增，供复查时直接引用）

> ⚠️ 本节是**后补的事实更新**，不属于原文，也不改变 DR-001 的结论。

| 项 | 内容 |
| --- | --- |
| 数据出处 | `devlog/day14.md`「A/B 对照（20 用例 × 2 组 = 80 轮，真实 API）」；原始数据归档 `docs/eval-results/ab-metrics-v3.3.0.json`、`ab-blind-v3.3.0.json`、`ab-key-v3.3.0.json` |
| 实测结果 | 平均端到端延迟 **A 多智能体 2146.6 ms / B 单模型 1376.0 ms**；平均首字延迟 **1888.2 ms / 1113.5 ms**；AI 腔轮次占比 **0.0% / 0.0%**；平均问号/感叹号 **0/0 — 0/0**；平均字数 **37.9 / 39.5**；危机协议轮次 **2 / 2** |
| 诚实结论（原文） | 「在可客观测量的指标上，**多智能体没有带来可观察改善，却让延迟增加 56%—70%**」 |
| 必须一起读的局限（原文） | 「客观指标很粗，**测不到「像不像真人」**——那需要人工盲评（未完成）。所以只能说「在这几项指标上没看到差异」，**不能说「无效」**」 |
| 判定规则（引自 `docs/upgrade-plan-v3.md` §3.5） | 「采用 v4 ⇔ 出戏率显著下降 **且** 盲评 95% CI 下界 >50% **且** 调用次数降 ≥30% **且** 危机召回不退化。**若只满足「省钱」，不允许上线。**」 |
| 台账缺口 | ⚠️ A/B 与红队脚本**没有记录 token 用量**（只采集字符数与延迟），所以仓库里**没有实测 token 数**；`logs/usage_summary.md` 里凡估算都已标注为估算 |

## 五、本文件何时需要更新

满足**任意一条**就必须回来改 `docs/ADR.md`：

1. **新增一条 DR**：出现 §1.1 五类触发条件中的任意一类；
2. **某条 DR 的复查触发条件被满足**：必须回来**追加**一段「复查结果」，
   **不许直接改写原条目的结论**（原文要留着，才能看出当时的判断是否站得住）；
3. **某条 DR 的结论被推翻**：新增一条 DR（例：`DR-001R` 或 DR-014）说明「因为什么被推翻、改成什么」，
   并**在 DR-001 里加一行指向新条目的链接**，而不是删掉 DR-001；
4. **已知代价被实测证实或证伪**：把数字补进该条目的「已知代价」或 §3.3 那样的「事实状态」小节；
5. **建议清单里的某条被正式写成 DR**：从 §四 的表格里**移除该行**（或标注「已收录为 DR-0XX」），避免清单与正文重复；
6. **模板字段变化**（§二，例如增加必填字段）：要同步更新 §四 清单里对素材的说明；
7. **§1.1 / §1.2 的判据变化**：什么该写、什么不该写，标准变了就要改机制说明。

> 维护口诀：**DR 是「可以追溯的立场」，不是「最新的说明书」。
> 立场变了就**追加**，不要**覆盖**——覆盖掉的是我们当初为什么会这么想的证据。**
