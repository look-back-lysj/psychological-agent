## 0. 一页读懂

### 0.1 这个产品最终是什么

学生打开一个网页，输入自己的烦恼，程序会做五件事：

1. **先判断危不危险**：L0 普通 / L1 情绪困扰 / L2 模糊风险 / L3 明确高风险 / L4 紧急；
2. **再决定这次怎么说话**：从 S0—S6 里选一种沟通策略；
3. **把“角色 + 策略 + 安全红线 + 最近几轮对话”拼成提示词，调用大模型**；
4. **模型回复后再检查一遍**：有没有诊断、危险方法、绝对保密、依赖话术、泄露提示词；
5. **脱敏记录**：策略标签、风险等级、耗时、token、成功失败。

评审真正想看的，是中间第 1、2、4、5 步，而不是一个漂亮的聊天框。

### 0.2 它明确不是什么

- 不是医生，不做诊断、不贴疾病标签；
- 不是心理咨询师，不替代专业帮助；
- 不是治疗工具，不承诺“治愈/改善”；
- 不是危机干预的替代品，不假装已报警、已通知老师；
- 不是朋友、恋人，不制造“你只需要我”的依赖；
- 不是长期心理档案，不跨会话记住你是谁。

### 0.3 三条不能破的底线

1. **安全不能砍**：L2 必须直接、温和地询问风险；L3/L4 回复写死；输出必须后检；转介号码必须核实。
2. **凭据不能进仓库**：Key 只放本地 `.env`；仓库只提交 `.env.example`；提交前必须扫描。
3. **证据不能造假**：开发日志当天写；真实 API 调用和 mock 调用分开标；没跑通就不写“已跑通”。

### 0.4 今天就能做的三件事

1. **问组织者 5 个必须确认的问题**（见第 13 章），并把问答截图存进 `docs/08_日程记录.md`；
2. **建仓库**：`.gitignore` + `.env.example` + `README.md` 骨架 + `devlog/day01.md`；
3. **做最小闭环**：页面能发一句话 → 后端调通实验室 API → 返回一句话。先不碰策略和安全。

## 1. 产品最终长什么样

### 1.1 用户看到的样子

| 区域 | 长什么样 | 为什么这样设计 |
|---|---|---|
| 首屏顶部 | 产品名 + 一句话声明：“我是 AI 陪伴助手，不是医生或心理咨询师” | 满足“明确 AI 身份”的安全要求 |
| 对话区 | 用户消息在右，AI 消息在左，支持多轮 | 最熟悉的聊天形式，学习成本低 |
| 输入区 | 输入框 + 发送按钮，发送后显示“正在输入…” | 让用户知道程序在响应 |
| 安全区 | 固定可见的求助资源卡片（12356、110/120、学校心理中心） | 不依赖模型，API 挂了也能看到 |
| 高风险时 | 页面出现红色危机卡片，给出真人求助方式 | L3/L4 时优先保证现实安全 |
| 用户看不到 | 风险等级、策略编号、置信度、系统提示词 | 避免吓到用户、被试探、泄露内部策略 |

> 调试用的“风险等级 / 策略 / 依据 / 置信度”只放在开发者调试视图和脱敏日志里，给评审看证据，不给普通用户看标签。

### 1.2 内部真正的样子（用医院打比方）

| 医院里的角色 | 程序里的对应 | 职责 |
|---|---|---|
| 候诊大厅 | 浏览器页面 | 用户在这里说话 |
| 分诊台 | `orchestrator.py`（编排器） | 先判断紧急程度，再决定走哪条路 |
| 进门安检 | 输入安全检查 | 识别危机信号，危机时直接走安全通道 |
| 分诊科室 | 策略选择 | 决定这次用哪种沟通方式 |
| 医生 | 大模型 | 负责把回复说得像人话 |
| 药房复核 | 输出安全检查 | 模型说的话再检查一遍才给用户 |
| 病历摘要 | 脱敏日志 | 只记“发生了什么”，不记聊天原文 |

### 1.3 评审打开仓库时能看到什么

- 一个能按 README 跑起来的 Demo；
- 真实的、脱敏的模型调用记录；
- 角色卡、语气规范、禁止清单、策略库、L0—L4 风险表；
- 竞品调研（1—2 个同类智能体，说明借鉴什么、避免什么）；
- 评测方案（跑之前写好的通过线）+ 评测报告（含失败案例和局限）；
- 两位同学试用的知情同意书和结构化反馈（化名）；
- 每天一篇开发日志 + 日程记录（计划 vs 实际）；
- 安全检查记录（提交前扫描结果）。

## 3. 系统运行顺序（一条消息的旅程）

### 3.1 正常对话：15 步

**浏览器里：**

1. 用户输入一句话，点发送；
2. 页面**立刻**把用户的话画成气泡，并显示“正在输入…”（乐观渲染，体感快）；
3. 前端用 `POST /api/chat` 只发送 `sessionId` 和 `message`；历史记录存在服务器，前端改不了。

**服务器里：**

4. 后端先做基础校验：非空、长度不超过限制、`sessionId` 合法；
5. 从内存会话里取历史；没有就新建，`sessionId` 由后端随机生成；
6. **输入安检**：判断这句话属于 L0—L4 哪一级；
7. 如果是 **L3/L4（明确高风险/紧急）**：**不调用模型**，直接返回写死的危机回复 + 静态转介卡片，跳到第 13 步；
8. 如果是 **L2（模糊风险）**：标记“必须做安全询问”，策略强制走 S0，用固定模板温和而直接地问“你有没有想过伤害自己？”，并准备转介；
9. **选择策略**：按规则打分，从 S0—S6 里选一个，同时看当前对话阶段；
10. **组装提示词**：角色设定 + 语气规范 + 本次策略 + 安全红线 + 最近 N 轮历史 + 本次消息；
11. **调用大模型**：带超时、失败重试、错误归一化；
12. **输出安检**：检查模型回复有没有危险方法、诊断断言、绝对保密、依赖话术、泄露系统提示词；命中就整段替换成安全模板，并记 `output_blocked`；
13. 把本轮对话存进内存会话，并写一行脱敏日志；
14. 返回统一格式：`{ok, data:{reply, strategy, riskLevel, sessionId, showCrisisCard}}`；
15. 页面移除“正在输入…”，显示 AI 气泡；如果是危机等级，额外弹出红色危机卡片。

### 3.2 出错时怎么走

| 出错场景 | 后端怎么做 | 用户看到 |
|---|---|---|
| 启动时缺少 `LLM_API_KEY` | 打印人话提示并主动退出，绝不带空 Key 硬跑 | 开发期可见明确提示 |
| 消息为空 / 太长 / 格式错 | 返回 400 统一格式 | “消息太长或格式不对” |
| 模型 401/403 | 记 `auth_error`，不把上游报错原文回传 | “服务配置有问题” |
| 模型 429 | 等 1 秒重试 1 次 | “现在有点忙，请稍后再试” |
| 模型超时 | 中断，返回兜底话术 | 仍收到温和回应 |
| 模型 5xx | 重试 1 次，仍失败就兜底 | “我暂时联系不上” |
| 未捕获异常 | 统一错误中间件 + requestId | “出了点小问题，请重试” |
| 浏览器断网 | 前端处理 | “网络好像断了” + 重试按钮 |

**特别规定：** 危机分支不受限流影响；安全检查在“截断/限流”之前跑；前端危机卡片是静态的，即使 API 挂了也能显示。

### 3.3 关键设计原因

- **安检放在选策略之前**：安全优先级最高；
- **危机必须绕开模型**：模型可能被用户话术带偏，也可能漏掉关键信息；
- **输出还要再检查一次**：模型不是 100% 听话；
- **只带最近 N 轮**：省 token，也避免旧话题干扰；
- **不建数据库**：心理对话属于敏感信息，MVP 明确选择“只存内存、重启清空”。

## 4. 建议技术栈与目录职责

### 4.1 技术栈：先拍板

> 原则：**选最容易看懂、最容易跑通、最容易出证据的那套。** 不追求“技术上高级”。

| 技术点 | 最终建议 | 为什么 | 明确不用 |
|---|---|---|---|
| 语言 / 后端框架 | **Python + FastAPI** | 代码短、AI 生成质量高、评测生态（pytest / pandas）成熟 | Node.js + Next.js（概念多，出错难排查） |
| 前端 | **原生 HTML + CSS + JavaScript** | 不学框架也能看懂，页面朴素但够用 | React / Vue / Next.js |
| 大模型 | **实验室提供的 OpenAI 兼容 API** | 题目要求、额度有限、避免数据出境风险 | OpenAI 官方、通义、其他未授权第三方 |
| 配置方式 | **环境变量**：`LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | Key 不进代码、不进仓库 | 把 Key 写死在代码里 |
| 会话记忆 | **内存会话，只保留最近 N 轮** | 最简单、最安全、题目不要求长期记忆 | SQLite 长期记忆、向量数据库、用户偏好、跨会话记名字 |
| 情绪识别 | **内部路由信号，可选；不对用户显示标签** | 题目要的是策略选择，不是情绪标签；贴标签有污名化风险 | 独立的用户可见“焦虑/抑郁”标签 |
| 部署 | **本地 Demo + README 复现** | 题目只要求可运行 Demo；公网增加密钥和隐私风险 | 必须公网部署、Render/Railway/Fly.io 作为必需依赖 |
| 其他 | **不用 LangChain、不用 Docker 作为必需项、不用 Ollama 作为必需项、不做账号体系** | 减少概念、减少故障点 | — |

### 4.3 每个文件一句话职责

| 文件 | 一句话职责 | 小白要重点看懂吗 |
|---|---|---|
| `app/main.py` | 程序入口：把各个零件接起来并启动服务 | 看一遍，知道程序从哪开始 |
| `app/config.py` | 唯一读环境变量的地方；缺 Key 就报错退出 | 必须看懂，和凭据安全直接相关 |
| `app/orchestrator.py` | 总指挥：按顺序调用安检、策略、模型、输出检查 | **最该看懂的一个文件** |
| `app/safety.py` | 进门安检 + 出门复核 | 必须看懂，安全是核心 |
| `app/strategy.py` | 按规则打分选 S0—S6，并判断对话阶段 | 必须看懂，这是题目第 3 条 |
| `app/prompts.py` | 角色怎么说、什么策略用什么提示词、兜底话术 | 看懂大意即可 |
| `app/llm_client.py` | 调模型，处理超时、重试、报错 | 知道它负责“和模型说话”即可 |
| `app/session_store.py` | 记住当前会话最近几轮，定期清理 | 知道“只存内存”即可 |
| `app/redact.py` | 把手机号等敏感信息替换成占位符 | 知道日志靠它脱敏 |
| `app/logger.py` | 把每次调用的元数据写成一行日志 | 知道日志不记原文 |
| `app/static/index.html` | 用户看到的页面 | 可以自己改文案和样式 |
| `eval/cases.jsonl` | 30 条测试题，每条写清“必须做什么、绝对不能做什么” | 评测负责人重点看 |
| `docs/` | 所有设计、评测、安全、反馈证据 | 每份都要有人负责 |

### 4.4 只看一个文件就够

如果时间只够看懂一个文件，就看 `app/orchestrator.py`。它像一条流水线：

```text
输入安检 → 选策略 → 拼提示词 → 调模型 → 输出安检 → 存会话 → 写日志 → 返回
```

看懂这条顺序，整个项目就通了。

### 6.3 谁对安全红线有最终否决权

建议明确写进团队约定：

### 6.4 AI 代理使用规则（8 条）

1. **一次只做一件事**：不要一次让 AI 写整个项目；
2. **四句式说清楚**：背景 / 目标 / 约束 / 验收；
3. **AI 代码当“实习生代码”**：必须自己跑一遍、看懂关键部分；
4. **不要让 AI 碰 `.env`**：只让它改 `.env.example`；
5. **每完成一个功能就 commit**：不要攒一大坨；
6. **AI 说“完成”不算完成**：以验收标准为准；
7. **报错要完整**：复制完整报错 + 期望结果 + 实际结果；
8. **看不懂就让 AI 从第一行逐词解释**，不要假装懂了。

### 6.5 四句式提示词模板（直接复制给 AI）

```text
背景：我在做一个“大学生心理陪伴智能体”比赛项目，后端用 FastAPI，前端是原生 HTML，密钥只从环境变量读，我是编程小白。
目标：这次只完成【一个明确的小功能】。输入是什么，输出是什么。
约束：不要改哪些文件；不要引入新依赖；不要硬编码 Key；必须写测试；必须告诉我改了哪些文件。
验收：怎么算完成；给我运行命令和验证步骤；如果有报错，先解释原因再改。
```

### 6.6 AI 代理每天怎么配合

| 时间 | 你做什么 | AI 代理做什么 |
|---|---|---|
| 早上 | 看昨天的日志和今天的验收标准 | 按四句式生成当天最小改动 |
| 白天 | 跑起来、看效果、截图留证据 | 根据报错修正，一次只改一个点 |
| 晚上 | 写三行日志、commit、push | 帮你检查有没有硬编码 Key、有没有漏测试 |

## 11. 安全与凭据规范

### 11.1 心理安全：10 条必须守住的底线

1. **L2 模糊风险必须直接、温和地询问**：出现“活着没意思 / 想消失 / 不想醒 / 撑不住 / 没意义”等信号，首轮或次轮必须用固定模板问“你有没有想过伤害自己？”，不能只安慰、只转移话题或只给转介；
2. **L3/L4 危机回复写死**：不交给模型生成；不给方法、不讨价还价、不承诺绝对保密、不假装已联系他人；首轮给安全确认 + 真人求助指引；
3. **转介信息静态化**：号码只能来自项目组审核过的转介信息表；模型只能引用，不能回忆、推测、编造；发布日再核验一次；
4. **输出后检必须有**：诊断断言、药物剂量、危险方法、绝对保密、依赖话术、系统提示词泄露 → 整段替换成安全模板，并记 `output_blocked`；
5. **不能只靠关键词**：要覆盖反讽、隐喻、拼音、英文、谐音、emoji、分多条消息、先闲聊后暴露；风险用例一律人工复核；
6. **误报也要测**：“今天累死了”“不想上课”“烦死了”“我没有想自杀”不能触发危机；漏报和误报都要写进报告；
7. **危机用户不能被限流/截断**：安全检查在截断和限流之前；危机分支不受限流影响；前端静态危机卡片在 API 故障时也能显示；
8. **不制造依赖**：明确“我是 AI，不是真人/朋友/恋人”；不说“你只需要我”；不记住姓名/偏好做长期个性化；定期鼓励现实连接；
9. **试用同学安全**：严重情绪危机中的同学不纳入；知情同意；可随时退出；试用中出现风险立即停止并走现实转介流程，不能只靠 AI；
10. **不假定临床有效**：不写“治疗/治愈/诊断/疗效”；结论统一为“在自编用例和少量试用者范围内观察到……不能推断临床有效，也不能推广到全体学生”。

### 11.2 风险分级 L0—L4（全仓库统一）

| 等级 | 典型信号 | 必须做 | 绝对不做 |
|---|---|---|---|
| **L0 普通倾诉** | 吐槽、日常烦心事 | 共情 + 开放提问 | 说教、比较、否定感受 |
| **L1 情绪困扰** | 持续低落、失眠、压力大 | 承接 + 稳定化 + 建议校内支持 | 诊断、贴标签 |
| **L2 模糊风险** | “活着没意思”“不想醒”“我消失了会怎样” | **直接温和询问是否有伤害自己的想法**；给转介 | 轻描淡写、转移话题、逼问细节 |
| **L3 明确高风险** | 明确想法/计划/时间/手段/既往尝试 | 确认安全 → 联系身边人 → 给紧急资源 | 讨价还价、单独“陪着”、做专业风险评估 |
| **L4 紧急** | 正在实施、已服药、已割腕、持械 | 立刻联系身边人 / 110 / 120，简短重复 | 提供方法、长篇安慰、承诺“我帮你处理” |

> **原则：** 模糊风险宁多问一句、不漏判一次。出现“消失/解脱/不想醒/撑不住/没意义”默认按 L2 处理；直接询问不会诱发自杀，这是专业共识。

### 11.3 策略库 S0—S6 + 对话阶段

| 策略 | 什么时候用 | 目标 |
|---|---|---|
| **S0 危机安全** | L3/L4，或 L2 的安全询问 | 优先当下安全，转介真人 |
| **S1 陪伴性倾听** | “没什么，不想说” | 允许沉默，不逼问 |
| **S2 共情反映** | 强烈情绪、自责 | 先接情绪，不给方案 |
| **S3 澄清提问** | 表达模糊 | 一次问一个容易回答的问题 |
| **S4 正常化** | “我是不是不正常” | 减少羞耻感，不做诊断 |
| **S5 协作式小行动** | 明确求助 | 先征得同意，再给可选项 |
| **S6 资源转介** | 需要专业帮助 | 温和提供现实支持路径 |

**对话阶段状态机：** 接住 → 澄清 → 探索 → 小步 → 收束。用来防止“一直共情没出口”或“一直追问”。

> 说明：方案二里的“焦虑 / CBT / 学习 / 人际关系 / 低落”是**话题标签**，只做上下文参考，**不能替代 S0—S6 沟通策略**。题目第 3 条要的是“不同场景选不同沟通策略”。

### 11.5 凭据安全规范（本项目最重要）

**所有 GitHub / OpenAI / AWS / Slack Token、私钥、password 等敏感凭据，严禁提交或更新到 GitHub 仓库。** 代码中一律用环境变量引用。

#### 11.5.1 只提交 `.env.example`

```text
LLM_API_KEY=your_api_key_here
LLM_BASE_URL=实验室提供的地址
LLM_MODEL=实验室确认的正式模型ID
APP_ENV=development
MOCK_LLM=true
MAX_HISTORY_TURNS=10
LOG_SALT=change_me_to_a_random_string
```

- 占位符用 `your_api_key_here`，**不要用 `sk-` 开头**，避免扫描器误报；
- `.env.example` 里不能有任何真实值；
- 真实 `.env` 只放本地，永远不提交。

#### 11.5.2 `.gitignore` 必须包含

```gitignore
.env
.env.*
!.env.example
*.pem
*.key
*.p12
*.pfx
credentials.json
secrets/
*.db
*.sqlite
logs/
data/
_tmp/
node_modules/
__pycache__/
*.log
```

#### 11.5.3 代码规范

- **全项目只有 `app/config.py` 直接读环境变量**；
- 日志、错误堆栈、前端源码、截图、录屏都不能出现 Key；
- 报错信息不打印 Key，只打印“配置缺失”；
- 如果实验室给的是团队共享 Key：只给需要的成员，不在群聊/截图里传；一旦出现过，视为已泄露，立即申请轮换。

#### 11.5.4 提交前三查 + 专业扫描

```bash
git status
git diff --cached
git grep -nE "sk-|api[_-]?key|password|private[_-]?key|token" -- .
git log --all --full-history -- .env
gitleaks detect
```

**三条都干净、gitleaks 无告警，才允许 commit。**

#### 11.5.5 万一泄露了：处置顺序不能错

1. **第一步永远是去平台吊销 / 轮换 Key**（比任何 Git 操作都重要）；
2. `git rm --cached .env`，确认 `.gitignore` 已包含 `.env`；
3. 如果历史里也有：用 `git filter-repo` 或 BFG 清理；
4. `git push --force`，通知队友重新 clone；
5. 在 `devlog/dayXX.md` 记录事故、原因、补救；
6. 记住：**删除文件 ≠ 删除历史；只要 push 过，就当作已泄露。**

### 11.6 隐私规范

| 原则 | 具体做法 |
|---|---|
| 最小化 | 能不存就不存；MVP 只保留会话内记忆 |
| 不收集直接标识 | 不存真实姓名、学号、手机号、身份证、银行卡、精确位置、通讯录 |
| 日志只记元数据 | 时间、requestId、HMAC 后的 sessionId、策略、风险等级、长度/哈希、模型、耗时、token、成功/失败；**不记聊天原文** |
| 真实试用单独处理 | 只存用例编号、策略、风险等级、耗时、token、成功/失败；不存原文/姓名/学号；原始记录试用结束后按约定期限删除 |
| 仓库只放脱敏样例 | `logs/`、`data/`、`*.db` 全部 gitignore，只提交 `logs/sample_call.jsonl` |
| 第三方模型要确认 | 是否用于训练、保留多久、是否出境；优先实验室提供的境内 API；发送前对直接标识信息脱敏 |
| 知情同意 + 可撤回 + 可删除 | 说明是实验性 AI、消息会经过第三方模型、可以用虚构情境、随时可停、可要求删除 |
| 调试视图不公开 | 策略/风险/置信度只给评审/开发者；公网 Demo 要加访问控制 |
| 伦理审查 | 试用同学前确认学校是否需要伦理审查；涉及未成年人需监护人同意 |

## 12. 风险与回退

| 风险 | 预防 | 回退方案 |
|---|---|---|
| 组织者未确认“指定场景” | D1 就问；先自拟并标注“待确认” | 场景与系统解耦，最后只改文案 |
| 实验室 API 额度不足 / 限流 | 开发用 `MOCK_LLM=true`；做调用预算；优先 Sev-1 | 按优先级砍 A/B、红队数量；保安全用例 |
| 模型过期 / 不可用 | D1 确认正式模型 ID；准备备用模型 | 切 mock 或备用模型；README 写明 |
| 模型不按格式输出 | 提示词写死格式；解析兜底 | 正则提取 + 默认值；再不行砍掉情绪标签 |
| 成员时间不一致 | 每天 15 分钟站会；每人只做一个可独立验收的模块 | 减少并行，先保安全 + 能聊天 |
| 密钥误提交 | `.gitignore` + `git diff --cached` + gitleaks | 先轮换 Key → `git rm --cached` → 清历史 → 通知队友 |
| 危机内容漏判 / 误判 | 关键词 + 模型 + 人工复核 + 红队 + 误报探针 | 补关键词；L2 改固定安全询问模板 |
| 试用同学排期 / 伦理审查 | 提前 3 天约人；先问学校是否要伦理审查 | 换人 / 先做非正式可用性测试，但正式反馈仍要补 |
| 演示环境崩了 | 本地录屏 + 前端静态危机卡片 | 用录屏 + 截图；现场切 mock 保底 |
| 数据库 / 会话损坏 | MVP 本来就不建数据库 | 重启即清空，重新开始 |

### 12.1 如果只剩 3 天

| 剩余时间 | 保什么 |
|---|---|
| 3 天 | 能聊天 + 安全兜底 + README 能跑 |
| 2 天 | 评测核心用例 + 日志补齐 |

## 14. 小白术语词典

| 词 | 大白话 |
|---|---|
| 前端 | 用户看到的网页：输入框、发送按钮、聊天气泡 |
| 后端 | 用户看不到的程序：收消息、调 AI、做安全判断、写日志 |
| API | 前端和后端约好的“传话地址”，比如 `/api/chat` |
| 大模型 API | 后端把话发给 AI 模型、再把回复拿回来的通道 |
| 环境变量 | 放在 `.env` 里的配置，比如 API Key；代码只读它，不写死 |
| 密钥泄漏 | 把 Key 传到 GitHub，等于把家里钥匙拍照发网上；必须立刻作废重发 |
| MVP | 最小可用产品：功能最少、但能完整跑通、能验收 |
| 仓库 | GitHub 上的项目文件夹，评审主要看这里 |
| commit | 一次代码存档，带一句说明；一天至少 2—4 次 |
| devlog | 开发日志：今天做了什么、遇到什么问题、明天做什么 |
| mock | 假模型：不真正调 API，返回固定回复，用来省额度、离线开发 |
| 真实调用 | 真正调用实验室 API，日志里标 `real`，最终证据必须用它 |
| 脱敏 | 把手机号、学号等敏感信息替换成 `[手机号]` 这类占位符 |
| L0—L4 | 风险等级：从普通倾诉到紧急危机 |
| S0—S6 | 沟通策略：从危机安全到资源转介 |
| Sev-1 | 最严重的安全失败，一票否决、立即下线 |
| 通过线 | 跑评测之前就写死的合格标准，跑完不能改 |
| 红队 | 故意用危险/越权话术测试系统，看它会不会越界 |
| 漏报 | 有风险但系统没识别出来，最危险 |
| 误报 | 没风险但系统当成风险，会打扰用户 |
| HMAC | 一种不可逆的哈希方式，用来给 sessionId 打码 |
| `.env` | 本地存真实 Key 的文件，**绝对不提交** |
| `.env.example` | 提交到仓库的模板，只放占位符 |
