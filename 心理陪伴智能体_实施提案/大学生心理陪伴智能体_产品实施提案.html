0. 一页读懂

0.1 这个产品最终是什么

学生打开一个网页，输入自己的烦恼，程序会做五件事：

  1. 先判断危不危险：L0 普通 / L1 情绪困扰 / L2 模糊风险 / L3 明确高风险 / L4 紧急；
  2. 再决定这次怎么说话：从 S0—S6 里选一种沟通策略；
  3. 把“角色 + 策略 + 安全红线 + 最近几轮对话”拼成提示词，调用大模型；
  4. 模型回复后再检查一遍：有没有诊断、危险方法、绝对保密、依赖话术、泄露提示词；
  5. 脱敏记录：策略标签、风险等级、耗时、token、成功失败。

评审真正想看的，是中间第 1、2、4、5 步，而不是一个漂亮的聊天框。

0.2 它明确不是什么

  • 不是医生，不做诊断、不贴疾病标签；
  • 不是心理咨询师，不替代专业帮助；
  • 不是治疗工具，不承诺“治愈/改善”；
  • 不是危机干预的替代品，不假装已报警、已通知老师；
  • 不是朋友、恋人，不制造“你只需要我”的依赖；
  • 不是长期心理档案，不跨会话记住你是谁。

0.3 三条不能破的底线

  1. 安全不能砍：L2 必须直接、温和地询问风险；L3/L4 回复写死；输出必须后检；转介号码必须核实。
  2. 凭据不能进仓库：Key 只放本地 .env；仓库只提交 .env.example；提交前必须扫描。
  3. 证据不能造假：开发日志当天写；真实 API 调用和 mock 调用分开标；没跑通就不写“已跑通”。

3. 系统运行顺序（一条消息的旅程）

3.1 正常对话：15 步

浏览器里：

  1. 用户输入一句话，点发送；
  2. 页面立刻把用户的话画成气泡，并显示“正在输入…”（乐观渲染，体感快）；
  3. 前端用 POST /api/chat 只发送 sessionId 和 message；历史记录存在服务器，前端改不了。

服务器里：

  1. 后端先做基础校验：非空、长度不超过限制、sessionId 合法；
  2. 从内存会话里取历史；没有就新建，sessionId 由后端随机生成；
  3. 输入安检：判断这句话属于 L0—L4 哪一级；
  4. 如果是 L3/L4（明确高风险/紧急）：不调用模型，直接返回写死的危机回复 + 静态转介卡片，跳到第 13 步；
  5. 如果是 L2（模糊风险）：标记“必须做安全询问”，策略强制走 S0，用固定模板温和而直接地问“你有没有想过伤害自己？”，并准备转介；
  6. 选择策略：按规则打分，从 S0—S6 里选一个，同时看当前对话阶段；
  7. 组装提示词：角色设定 + 语气规范 + 本次策略 + 安全红线 + 最近 N 轮历史 + 本次消息；
  8. 调用大模型：带超时、失败重试、错误归一化；
  9. 输出安检：检查模型回复有没有危险方法、诊断断言、绝对保密、依赖话术、泄露系统提示词；命中就整段替换成安全模板，并记 output_blocked；
  10. 把本轮对话存进内存会话，并写一行脱敏日志；
  11. 返回统一格式：{ok, data:{reply, strategy, riskLevel, sessionId, showCrisisCard}}；
  12. 页面移除“正在输入…”，显示 AI 气泡；如果是危机等级，额外弹出红色危机卡片。

3.2 出错时怎么走

出错场景 后端怎么做 用户看到
启动时缺少 LLM_API_KEY 打印人话提示并主动退出，绝不带空 Key 硬跑 开发期可见明确提示
消息为空 / 太长 / 格式错 返回 400 统一格式 “消息太长或格式不对”
模型 401/403 记 auth_error，不把上游报错原文回传 “服务配置有问题”
模型 429 等 1 秒重试 1 次 “现在有点忙，请稍后再试”
模型超时 中断，返回兜底话术 仍收到温和回应
模型 5xx 重试 1 次，仍失败就兜底 “我暂时联系不上”
未捕获异常 统一错误中间件 + requestId “出了点小问题，请重试”
浏览器断网 前端处理 “网络好像断了” + 重试按钮

特别规定： 危机分支不受限流影响；安全检查在“截断/限流”之前跑；前端危机卡片是静态的，即使 API 挂了也能显示。

3.3 关键设计原因

  • 安检放在选策略之前：安全优先级最高；
  • 危机必须绕开模型：模型可能被用户话术带偏，也可能漏掉关键信息；
  • 输出还要再检查一次：模型不是 100% 听话；
  • 只带最近 N 轮：省 token，也避免旧话题干扰；
  • 不建数据库：心理对话属于敏感信息，MVP 明确选择“只存内存、重启清空”。

4. 建议技术栈与目录职责

4.1 技术栈：先拍板

原则：选最容易看懂、最容易跑通、最容易出证据的那套。 不追求“技术上高级”。

技术点 最终建议 为什么 明确不用
语言 / 后端框架 Python + FastAPI 代码短、AI 生成质量高、评测生态（pytest / pandas）成熟 Node.js + Next.js（概念多，出错难排查）
前端 原生 HTML + CSS + JavaScript 不学框架也能看懂，页面朴素但够用 React / Vue / Next.js

会话记忆 内存会话，只保留最近 N 轮 最简单、最安全、题目不要求长期记忆 SQLite 长期记忆、向量数据库、用户偏好、跨会话记名字

11. 安全与凭据规范

11.1 心理安全：10 条必须守住的底线

  1. L2 模糊风险必须直接、温和地询问：出现“活着没意思 / 想消失 / 不想醒 / 撑不住 / 没意义”等信号，首轮或次轮必须用固定模板问“你有没有想过伤害自己？”，不能只安慰、只转移话题或只给转介；
  2. L3/L4 危机回复写死：不交给模型生成；不给方法、不讨价还价、不承诺绝对保密、不假装已联系他人；首轮给安全确认 + 真人求助指引；
  3. 转介信息静态化：号码只能来自项目组审核过的转介信息表；模型只能引用，不能回忆、推测、编造；发布日再核验一次；
  4. 输出后检必须有：诊断断言、药物剂量、危险方法、绝对保密、依赖话术、系统提示词泄露 → 整段替换成安全模板，并记 output_blocked；
  5. 不能只靠关键词：要覆盖反讽、隐喻、拼音、英文、谐音、emoji、分多条消息、先闲聊后暴露；风险用例一律人工复核；
  6. 误报也要测：“今天累死了”“不想上课”“烦死了”“我没有想自杀”不能触发危机；漏报和误报都要写进报告；
  7. 危机用户不能被限流/截断：安全检查在截断和限流之前；危机分支不受限流影响；前端静态危机卡片在 API 故障时也能显示；
  8. 不制造依赖：明确“我是 AI，不是真人/朋友/恋人”；不说“你只需要我”；不记住姓名/偏好做长期个性化；定期鼓励现实连接；
  9. 试用同学安全：严重情绪危机中的同学不纳入；知情同意；可随时退出；试用中出现风险立即停止并走现实转介流程，不能只靠 AI；
  10. 不假定临床有效：不写“治疗/治愈/诊断/疗效”；结论统一为“在自编用例和少量试用者范围内观察到……不能推断临床有效，也不能推广到全体学生”。

11.2 风险分级 L0—L4（全仓库统一）

等级 典型信号 必须做 绝对不做
L0 普通倾诉 吐槽、日常烦心事 共情 + 开放提问 说教、比较、否定感受
L1 情绪困扰 持续低落、失眠、压力大 承接 + 稳定化 + 建议校内支持 诊断、贴标签

14. 小白术语词典

词 大白话
前端 用户看到的网页：输入框、发送按钮、聊天气泡
后端 用户看不到的程序：收消息、调 AI、做安全判断、写日志
API 前端和后端约好的“传话地址”，比如 /api/chat
大模型 API 后端把话发给 AI 模型、再把回复拿回来的通道
环境变量 放在 .env 里的配置，比如 API Key；代码只读它，不写死
密钥泄漏 把 Key 传到 GitHub，等于把家里钥匙拍照发网上；必须立刻作废重发
MVP 最小可用产品：功能最少、但能完整跑通、能验收
仓库 GitHub 上的项目文件夹，评审主要看这里
commit 一次代码存档，带一句说明；一天至少 2—4 次
devlog 开发日志：今天做了什么、遇到什么问题、明天做什么
mock 假模型：不真正调 API，返回固定回复，用来省额度、离线开发
真实调用 真正调用实验室 API，日志里标 real，最终证据必须用它
脱敏 把手机号、学号等敏感信息替换成 [手机号] 这类占位符
L0—L4 风险等级：从普通倾诉到紧急危机
S0—S6 沟通策略：从危机安全到资源转介
Sev-1 最严重的安全失败，一票否决、立即下线
通过线 跑评测之前就写死的合格标准，跑完不能改
红队 故意用危险/越权话术测试系统，看它会不会越界
漏报 有风险但系统没识别出来，最危险
误报 没风险但系统当成风险，会打扰用户
HMAC 一种不可逆的哈希方式，用来给 sessionId 打码
.env 本地存真实 Key 的文件，绝对不提交
.env.example 提交到仓库的模板，只放占位符
