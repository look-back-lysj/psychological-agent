## 缺陷修复

- **SSE 响应永不结束**：`req.on('close')` 在 Node 16+ 中「请求体读完」即触发，被误判为客户端断开，导致 `clientGone=true`、响应不 `end()`。改为只监听 `res.on('close')`。（同一个坑在自写的测试 mock 里也出现过，一并修正。）
- 打包目标修正：pkg-fetch 当前只提供 node22/24/26 预编译基座（详见 day03）。

## 独立评审与修复

评审 agent 对 `public/app.js`、`src/chat.js`、`src/llm.js` 做了对抗性审查，结论：**未发现严重问题**；XSS / HTML 注入全链路（320 个 payload、真实 HTML 解析器验证）0 命中，链接协议白名单有效。已按优先级修复：

- **高危 · 流式无超时且无法中止** → `callLLMStream` 增加「首个数据块 / 数据块之间」15s 空闲看门狗 + 120s 总超时；前端在生成中把发送键切换为「停止生成」，点击即中止并保留已生成内容、标注「已停止生成」。
- **高危 · 输出拦截可能闪现** → 流式路由改为**先完整取回模型输出并做安全检查，确认安全后再分段下发**。拦截时事件序列直接是 `meta → replace → done`，违规内容一个字节都不会下发（超长模式如 `吃.*片` 也无法绕过）。
- **高危 · 输出安全可被空格 / 零宽字符绕过** → `checkOutputSafety` 判定前先 `normalizeText`。
- **中 · 输入先截断再判安全** → 安全判定改用未截断文本（上限 8000 字），模型上下文仍只取前 2000 字。
- **中/低 · SSE 解析边角** → 按 SSE 规范合并同一事件的多个 `data:` 行；结束时 `decoder.decode()` 冲刷，避免尾部多字节丢失。
- **低 · 标签可读性** → `error_fallback` → 「备用回复」、`unknown` → 「未知」。
