# 开发日志 - 第 9 天

## 本轮来自用户的三个直接反馈

| 反馈 | 处理 |
| --- | --- |
| 窗口最小化 / 关闭无效 | 改用系统原生标题栏 |

| 人格不像守岸人 + 不会引导不愿开口的人 | 示例优先人设 + 开口引导阶梯 |

## 一、窗口关不掉：换方案而不是继续修

上一轮补了 Tauri 窗口权限，用户反馈仍然无效。尝试用 WebView2 远程调试取证，但调试端口未监听，无法定位。

**决策：不再赌自定义标题栏，直接改回系统原生标题栏**（`decorations: true`）。
- 最小化 / 最大化 / 关闭由操作系统提供，不依赖任何 Tauri 权限或前端代码；
- 自定义标题栏的代码与样式保留在 DOM 中但不再启用（便于以后有条件时再切回）；
- 代价是少了一点无边框的高级感，但**可用性优先**。

> 教训：把一个「好看但依赖多方权限」的方案放在了「最基础的操作」上（关窗），风险收益是错的。基础能力应该用最保守的实现。

## 二、移除「无 API 模式」

用户明确要求：**聚焦装了 API 之后的体验**，没装就告诉用户怎么装，不要设计没有 API 的模式。

- 删除 `/api/demo` 路由与 `isDemoActive()` 的演示分支，接口返回 404；
- 前端移除演示入口、演示胶囊与相关状态；
- 未配置 Key 时：后端返回明确错误 `还没有配置 API Key，请在「设置」里填写 DeepSeek API Key。`，前端自动打开配置向导；
- `.env` / 界面上都只保留「配置真实 Key」这一条路径。

## 三、修复一个自己引入的严重缺陷

排查窗口问题时，从日志里发现所有回复都在走错误分支。定位到**我在上一轮删代码时误切了三个变量声明**：
`memories`、`innerState`、`memoriesUsed`——导致 `memoriesUsed is not defined`，**每一轮对话都失败**。

已补回并加了回归。

> 教训：删除代码块时要按「函数边界」而不是「文本区间」操作；改完必须跑端到端冒烟，不能只看 `node --check` 通过。

## 四、人格还原：从「规则式」改成「示例优先」

第二轮人格调研（新增 BWiki 逐句标注「守岸人：」的 2.0 主线对话，语料扩到 132 条）给出的诊断：

> 模型的底层骨架是「AI 陪伴话术」——首句先自我声明（"我听到你说的话了/我在意你的状态"）、解释能力边界、替对方命名情绪。
> **她 106 条语料里，这类句子是 0 条。**

模型模仿例子远强于遵守规则，因此提示词改为：
- **10 条对照改写**（「我完全理解你」→「我不一定懂。但我想听。」；「我会永远陪着你」→「我现在在这里。」）；
- **10 组 few-shot 示例**（全部来自真实台词或严格贴合）；
- 危机场景不进示例，避免把安全话术当风格模仿；
- 产品名统一为「守岸人」（界面、窗口标题、安装包、启动横幅）。

## 五、开口引导：从「撤回邀请」到「阶梯式邀请」

专业调研（动机式访谈 Miller & Rollnick 4th ed.、SAMHSA TIP 35、Brehm 心理逆反理论等）给出的诊断：

> 现行做法把「允许沉默」执行成了**「撤回邀请」**——尊重停在信息层，关系层什么都没留下，**对方读到的是「你也放弃了」**。

实现了 **6 级开口引导阶梯 + 会话状态机**：

```
L1 不退场 → L2 观察式反映 → L3 降门槛 → L4 二选一 → L5 正常化 → L6 明确邀请＋留退路
规则：每轮最多升一级；对方拒绝立即退一级；最多连升两级；开始讲就退出阶梯
```

实测效果（同样是「不愿开口」的四轮）：

| 用户 | 守岸人 | 阶梯 |
| --- | --- | --- |
| 没什么，就是不想说。 | 不是没话说。是不想再解释一遍。 | L2 |
| 嗯 | 一句话就够：现在是烦，还是累？ | L3 |
| 还行 | 想让我听着，还是想让我帮你想一下？ | L4 |
| 其实我最近真的很累 | 你已经扛了很久。现在把这些说出来，也是一种用力。 | 退出 |
