## 一、为什么要做这次重构

产品负责人的原话：**「优化项目结构，使之更容易被不同的人（或者 AI）分模块优化」**，并要求
「先好好设计再改架构，注释清晰，利于以后的模块化优化与合作」。

现状问题：`src/` 是**平铺的 17 个文件**，看不出层次；根目录混着代码与比赛材料；

## 二、设计阶段：三路并行调研（都用实测而非印象）

### 2.1 后端分层设计
实测依赖图（自写拓扑分层脚本）：**17 文件 / 5 层 / 无循环依赖**。
被依赖最多（动它要小心）：`utils(7)`、`paths(5)`、`strategy(4)`；依赖最多（影响面大）：`chat(11)`、`routes(5)`。

**关键实测**：用探针确认 **pkg 能静态收集子目录 require 与目录级 `index.js`** →
加子目录零打包成本；且 `require('./chat')` 命中 `chat/index.js` 后
**`main.js` 的两处调用点一行都不用改**。

### 2.2 前端模块化设计
结论：**`app.js` 与 `style.css` 都不该拆**，理由都用实验数据支撑：

| 实测 | 结果 |
| --- | --- |
| ES modules 在 Tauri 下 | `http://` 可用；**`file://` 硬失败（CORS）** |
| `app.js` 耦合度 | `el` 96 键全文件访问数百处、**30 个可变 `let`**、`bindEvents` 单函数 **264 行调 49 个具名函数** → **没有叶子模块可拆** |
| 按章节拆 CSS | **技术上零丢失**（实测 539 条规则 = 539 条） |
| 但顺序敏感 | **136 处后写覆盖**（跨章节 78 + 同章节 58）；互换 §17/§18 实测 `.drawer` 的 `animation` 从 `none` 变 `drawer-in` |
| 反直觉发现 | **把 §00 令牌挪到末尾 → 0 差异**（CSS 变量按「谁最后谁赢」解析，与位置无关）。真正的雷是后写覆盖，不是变量位置 |

→ 结论：「行数大 ≠ 该拆」。拆文件只会把「闭包内隐式耦合」变成「跨文件隐式耦合」，
**风险上升、可读性不升**。改为**加可导航索引**。

## 四、🔴 本轮抓到的 3 个「验收项测不出」的静默缺陷（S3 阶段）

**这三个都不在任务书里、也都不在我的验收清单里**——是靠**真跑冒烟 + 查工作区多出什么**发现的。

| # | 缺陷 | 症状 | 为什么测不出 |
| --- | --- | --- | --- |
| 1 | `src/server.js` 的 5 处 require 未更新（`./sessions` 等） | 首次冒烟即 `Cannot find module './sessions'`，**服务根本起不来** | 我把任务描述简化为「去掉 `./src/` 前缀」，漏了这些模块也进了子目录 |
| 2 | 🔴 **`core/paths.js` 的 `appRoot()` 层级 bug** | **用户数据目录写错地方**：`data/`、`logs/` 落到 `src/` 下 | `node tests/run.js` **完全测不出**（测试只 require `safety`/`strategy`，不碰 `paths`）；是靠冒烟后 `git status` 冒出 `?? src/logs/` 才发现的 |
| 3 | 🔴 **`src/server.js` 的 `publicDir` 解析** | pkg 打出 `Cannot stat ENOENT src/public`，**打包后静态资源会 404** | 源码模式测不出（`appRoot` 优先命中）；只有跑 `npm run build` 才暴露 |

> **教训**：`__dirname` 相对路径对目录层级敏感，**这类 bug 单元测试测不出来**。
> 必须「真启动 + 真打包 + 检查工作区副作用」。已把这条写进 `AGENTS.md`。
