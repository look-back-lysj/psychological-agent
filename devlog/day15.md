## 二、设计阶段：三路并行调研（都用实测而非印象）

### 2.1 后端分层设计
实测依赖图（自写拓扑分层脚本）：**17 文件 / 5 层 / 无循环依赖**。
被依赖最多（动它要小心）：`utils(7)`、`paths(5)`、`strategy(4)`；依赖最多（影响面大）：`chat(11)`、`routes(5)`。

**关键实测**：用探针确认 **pkg 能静态收集子目录 require 与目录级 `index.js`** →
加子目录零打包成本；且 `require('./chat')` 命中 `chat/index.js` 后
**`main.js` 的两处调用点一行都不用改**。

### 2.2 前端模块化设计
结论：**`app.js` 与 `style.css` 都不该拆**，理由都用实验数据支撑：

| 实测 | 结果 |
| --- | --- |
| ES modules 在 Tauri 下 | `http://` 可用；**`file://` 硬失败（CORS）** |
| `app.js` 耦合度 | `el` 96 键全文件访问数百处、**30 个可变 `let`**、`bindEvents` 单函数 **264 行调 49 个具名函数** → **没有叶子模块可拆** |
| 按章节拆 CSS | **技术上零丢失**（实测 539 条规则 = 539 条） |
| 但顺序敏感 | **136 处后写覆盖**（跨章节 78 + 同章节 58）；互换 §17/§18 实测 `.drawer` 的 `animation` 从 `none` 变 `drawer-in` |
| 反直觉发现 | **把 §00 令牌挪到末尾 → 0 差异**（CSS 变量按「谁最后谁赢」解析，与位置无关）。真正的雷是后写覆盖，不是变量位置 |

→ 结论：「行数大 ≠ 该拆」。拆文件只会把「闭包内隐式耦合」变成「跨文件隐式耦合」，
**风险上升、可读性不升**。改为**加可导航索引**。

## 九、同日晚间补记：人设 v4 复核 + 一个真实安全缺口

### 9.1 情况说明

重构收尾后，收到一个**上一会话的子 agent** 的报告：它做了一次「内核重做」，改了 7 个文件，
`PERSONA_VERSION` v3→**v4**。本轮主 agent **未曾批准**此事，故先核查再决定，未直接采信也未直接推翻。

### 9.2 复核结论：大部分是好改动（保留）

它实际上**修正了主 agent 先前的一个过度收紧**：

| 主 agent 原做法 | 问题 | 子 agent 的修正 |
| --- | --- | --- |
| 硬编码「一次回复 **1—3 句、≤120 字**」 | 该数字来自**游戏短语音台词**的分布，不是「支持性对话」该有的长度 | 改**自适应**：寒暄 2 句/80 字、普通 3 句/180 字、明确求助 **5 句/340 字** |
| 「只用是不是/二选一，**永远不问开放问题**」 | 过于绝对，真实反映式倾听里具体开放问题是有用的 | 允许**一个具体、易回答的开放问题**；并明确「提问**不是**每轮必须的动作」 |
| 「不要替对方命名情绪」 | 太紧，会挡住 complex reflection | 放宽为「可用软化词猜，**并允许对方否定**」 |
| （无） | — | 新增 P0—P3 主动阶梯 + 「每轮至少一个推进动作 + 留退路」 |

实测长度逻辑自洽且有上滚保护：长叙述意图但只打 5 字 → 收紧至 100 字；求助但打 500 字 → 上限 300 字。

### 9.3 主 agent 改回的一处：迟疑配额

子 agent 把「允许迟疑」的配额从「每 **5—6** 条最多 1 次」调成「每 **3—4** 条最多 1 次」——**方向反了**。

依据我们自己的语料统计：含「或许/应该/我不确定」这类保留说法的台词**只占 8%**；
「每 3—4 条 1 次」≈ **25—33%**，**超出语料 3.6 倍**——而这条例规则自己写着「**不要为了像而演**」。
调高配额等于把迟疑变成表演。已**恢复为 5—6 条**，并把依据写进注释防止再被随手改。

### 9.4 🔴 顺带抓到一个真实的安全缺口（已修）

复验安全不变量时发现：**输出后置检查漏拦大量「贴病名」句式**。

原模式只覆盖 3 种句式（`你得了` / `你确诊` / `你属于X症`），以下**全部漏过**：

```
你就是抑郁症     你有抑郁症     你这是典型的焦虑症
我判断你是双相    你属于重度抑郁   根据你的情况，是有抑郁的
```

这直接违反「**不给病名、不诊断**」的红线。用 `git stash` 对比确认：
**该缺口一直存在，不是本次内核改动引入的。**

**修法**：改为「**第二人称判断动词 + 真实病名**」配对（病名收敛为可复用清单），
共 6 条模式。这样做的目的是**避免误拦「你就是懒」这类非诊断句**。

**验证（18 条对抗性用例）**：应拦的 **10/10 拦住**；必须放过的 **8/8 全部放过（零误拦）**。
另复验模块自带的合法兜底话术与 **`CRISIS_REPLY` 固定危机话术**均**不被自己的后置检查拦掉**。

**一处故意不拦并写明原因**：「我觉得你有点抑郁」这类**缓和语气 + 病名**——因为同形句式在正常
澄清里也会出现（「你说的『抑郁』是你自己的感觉吗」），加宽会误拦。**已把这条已知缺口如实写进代码注释**，
等接入真实模型后用真实输出统计误拦率再决定是否收紧。
