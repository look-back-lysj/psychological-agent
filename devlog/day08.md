# 开发日志 - 第 8 天

## 目标

承接上一轮的复查结论，按「对产品价值的边际收益」排优先级，补掉四个真短板。

## 一、本轮打的四个点

| 优先级 | 问题 | 为什么值得做 |
| --- | --- | --- |
| P0 | 多智能体让首字延迟变高（每条消息都跑全流程） | 直接违背「丝滑」，且简单寒暄也浪费一次调用 |
| P0 | 验收要求的 **L2 人工评分 / L4 红队**还没做 | 赛题硬性要求的四层评测缺两层 |
| P1 | 「重试」会重复写入服务端会话历史 | 多轮上下文被污染（早前评审发现，一直没修） |
| P1 | 记忆「用到了哪条」不透明 | 「它记得我」要看得见才成立 |

## 二、自适应三档流水线（省调用、保丝滑）

不是每条消息都值得跑完整流水线：

| 档位 | 触发 | 调用次数 | 实测 |
| --- | --- | --- | --- |
| `minimal` | L0 且（去标点 ≤6 字 或 与上一条相似度 ≥0.9） | **1**（只跑「书」） | 「嗯」「谢谢」→ 1 次 |
| `standard` | 其余 L0/L1/L2 | **2**（「观」+「书」） | 长句倾诉 → 2 次 |
| `reviewed` | 本地快检命中 | **3**（+「校」） | AI 腔回复 → 3 次 |
| `crisis` | L3 | **0** | 「我不想活了」→ 0 次，走固定协议 |

- `minimal` 档**仍然用规则层选出的策略**，不会因为省一次调用就退化成无脑回复；
- 同会话内相同消息的「观」结果会缓存复用（上限 20 条）；
- L2 强制走 `standard`，L3 不进流水线。

## 四、正确性与透明度

- **重试去重**：请求体支持 `retry:true`；命中时保留已有用户消息、删除其后旧助手回复，不再重复追加；找不到对应轮次则防御性降级为普通请求。前端已接线。
- **记忆透明**：`done.memoriesUsed` 透传本轮真正注入提示词的记忆，助手消息下方以极轻的「用到了：…」呈现（最多 2 条 + 等 N 条，hover/聚焦看全文，幂等不重复），记忆面板对最近用过的条目加淡标记。
- **无障碍**：抽屉与侧边栏 `inert` + `aria-hidden`（无 `inert` 时降级）、打开聚焦首个可聚焦项、Tab 循环、Esc 关闭并归还焦点、`aria-expanded` 同步；新增 `?` 快捷键帮助与 `Ctrl/Cmd+K` 新建对话；消息区去掉 `aria-live`，改为隐藏的 `#sr-live` 仅在回复完成时播报。
- **localStorage 可靠性**：写入失败提示一次；数据损坏先备份到 `psych.sessions.corrupt.<ts>` 再降级，并提示用户。

## 五、一键构建（顺手解决的大坑）

`npm run desktop` 现在**在含中文的路径、无管理员权限的机器上也能一条命令跑通**：
脚本会自动把源码暂存到 ASCII 目录、自动沿用装在 ASCII 路径的 Rust 工具链、自动探测 MinGW、自动回收产物到 `dist/`。
另提供 `node scripts/build-desktop.js --check` 做纯环境预检。
